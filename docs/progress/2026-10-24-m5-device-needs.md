# M5 device evidence and remaining measurements

The iPhone 13 / iOS 27.0 LCK-only measurements in [#85](https://github.com/ziahamza/ios-voip-sdk/pull/85) supersede the original speculative multi-call table. The [device report](../research/callkit-simulator-probe/livecommunicationkit/multicall/README.md) measures system Hold/End/EndHeld & Accept, delayed/reversed/failed/pending constituents, configuration-dependent choices, capability-independent pause, app resume, merge/unmerge pass-through, lock-screen behavior and the absence of block-list filtering. These cases no longer need a first device pass.

Measured LCK behavior and simulator policy must remain distinct. LCK exposes neither transaction IDs nor group membership; runtime IDs are simulator correlation identifiers. The reported action `timeoutDate` remains 30 s, while measured effective expiry is about 5.3 s for Pause/End and 64 s for Join.

| Initial state | Action to measure | Evidence still needed |
| --- | --- | --- |
| A paused; B joined; configuration 2×1 | In one app `perform`, pause B and resume A | Constituent inventory/order, whether B remains paused rather than ending, delivery versus settlement, intermediate states and audio order. Repeat with reversed fulfillment, each failure and each pending constituent. This app-composed swap was not measured in #85. |
| A paused; B joined; configuration 2×1 | Resume A alone, delaying, failing or leaving Resume pending | When End B is generated relative to Resume delivery and settlement, whether A stays paused on failure/expiry, B state and audio order. #85 measures immediate successful Resume only; injected delayed-Resume ordering remains unverified. |
| A joined/paused and B incoming; genuine CallKit-only probe | Hold & Accept, End & Accept, End Held & Accept; app merge/unmerge | Actual `CXTransaction` identifiers/composition and public CallKit group behavior. LCK callbacks cannot supply these IDs or memberships. Use a separate probe without a simultaneous LCK manager (D13). |
| Ringing, joining and leaving calls near configured capacity | Incoming/start during each transition, then end/fail the existing call | Exactly which transient states consume capacity, when slots are released, error domain/code and timing. #85 already covers joined/paused capacity and Start error 7; repeat only the remaining transitions. |
| One otherwise valid conversation/action | Leave Start, Mute, tones, Merge and Unmerge pending | Effective expiry versus reported 30 s, cleanup callbacks, state and audio effects. Only Pause/End/Join effective deadlines are measured in #85. |
| Call already left after a failed or timed-out constituent | Immediately fulfill the generated cleanup End; compare fail/pending policies | Reproduce and bound #85's observed cleanup-End timeout after fulfillment, including action identity and duplicate callbacks. Keep the anomaly distinct from normal End settlement. |
| Relevant Settings conditions available | Incoming reports for restricted sharing, protected calls and sensitive participants | Codes 5–7: actual domain/code, report-to-completion interval, process survival and repeated-caller behavior. These remain unverified. Code 4 was measured absent for LCK; injected code 4 is a synthetic fault. |

For every run retain OS/build, configuration, full stable conversation/action UUIDs, monotonic and wall times, callback entry/exit, parameters and reported deadlines, fulfill/fail times, manager snapshots and audio callbacks. State explicitly whether an assertion comes from a public LCK observation, a genuine CallKit observation, or simulator policy. Cross-device/OS generalization remains unverified.
